## أ. الأدوار

| الدور | الصلاحيات |
|---|---|
| `owner` | كل شيء + الإعدادات المالية + حذف البيانات |
| `admin` | إدارة الطلبات والفريق والمحتوى |
| `writer` | كتابة ومراجعة نصوص القصص المسندة إليه |
| `illustrator` | Prompt Studio + رفع الصور للطلبات المسندة |
| `reviewer` | Quality Control + الموافقة على المراحل |
| `production` | الطباعة، التغليف، الشحن |
| `support` | التواصل مع العملاء، المعاينات، الملاحظات |
| *(العميل)* | بلا دور — الوصول عبر `public_token` فقط |

الأدوار عبر `spatie/laravel-permission`، والتطبيق عبر `OrderPolicy` و`AssetPolicy`.

قاعدة: `illustrator` و`writer` يريان **فقط** الطلبات المسندة إليهم، ولا يريان
بيانات الدفع، ولا صور الطفل إلا داخل الطلب المسند.

### 2. معالج الإنشاء `/create` — أهم شاشة في المشروع

8 خطوات، شريط تقدّم، حفظ تلقائي في `StoryDraft` (يمكن استكمالها لاحقًا برابط).

| # | الخطوة | الحقول |
|---|---|---|
| 1 | لمن الحكاية؟ | اسم الطفل، العمر (3-5 / 6-8 / 9-10)، طريقة المخاطبة (مذكر/مؤنث) |
| 2 | من هو؟ | صفات (اختيار متعدد + حر)، اهتمامات، شيء يحبه، شيء يخيفه، اللون المفضل |
| 3 | العالم | 5 عوالم عند الإطلاق (فضاء، غابة، بحر، مدينة الحكايات، المدرسة) |
| 4 | الهدف | شجاعة، ثقة بالنفس، حب المدرسة، صداقة، مغامرة خيالية |
| 5 | الأسلوب البصري | 3 أساليب كحد أقصى في البداية، بطاقات بصرية |
| 6 | الصور والموافقة | رفع 3–5 صور + شروط واضحة + checkbox موافقة ولي الأمر |
| 7 | الإهداء والمناسبة | نص الإهداء، المناسبة، تاريخ مطلوب |
| 8 | الباقة والدفع | الباقة، الإضافات، الكوبون، بيانات التوصيل، طريقة الدفع |

**عناصر التحويل داخل المعالج:**

- **معاينة غلاف حيّة**: بمجرد كتابة الاسم في الخطوة 1، يظهر غلاف mockup باسم الطفل.
  هذا أقوى محرّك تحويل في المنتج كله — نفّذه بدقة.
- **مقطع تشويقي مجاني** (AI): بعد الخطوة 4، زر «شوف كيف تبدأ حكايته» يولّد
  3 جُمل بالعربية باسم الطفل. مجاني، بدون صور، محدود بـ 3 محاولات/جلسة.
  (تفاصيل في `docs/03`، قسم Teaser.)
- شريط ثقة ثابت أسفل الشاشة: «صورك محمية · معاينة قبل الطباعة · تعديل مجاني».
- الخروج من الخطوة 6 بدون رفع صور مسموح → «أكمل لاحقًا» + إرسال رابط استكمال.

### 3. لوحة العميل `/orders/[token]`

رابط موقّع بدون حساب (MVP)، ثم حساب كامل لاحقًا.

يعرض:

- **خط رحلة بلغة طيوف** (7 مراحل، وليس حالات النظام الـ 19):

```
حكايتك وصلتنا  ✓
نكتب القصة     ✓
نرسم عالم طفلك ⏳
نجهّز الكتاب
بانتظار موافقتك
في الطباعة
في الطريق إليك 🚚
```

- المعاينة (PDF منخفض الدقة + علامة مائية) + زر **موافقة** وزر **طلب تعديل**.
- التعديل: يختار العميل الصفحة ويكتب ملاحظة → تُنشئ `RevisionRequest`.
- عدّاد التعديلات المتبقية حسب الباقة.
- الفاتورة، بيانات الشحن، رقم التتبع، ملف PDF النهائي بعد التسليم.
- زر «احذف صور طفلي الآن».

### 2. صفحة الطلب — 7 تبويبات

```
[نظرة عامة] [بيانات الطفل] [القصة] [الشخصيات] [البرومبتات والصور] [الكتاب] [التسليم]
```

**نظرة عامة** — الحالة، المسند إليه، المهل، سجل الحالات، التعليقات الداخلية، الدفع.

**بيانات الطفل** — كل مدخلات المعالج + الصور (خلف زر «إظهار» يسجّل في AuditLog)
+ حالة الموافقة + تاريخ الحذف المجدول.

**القصة** —
- زر «ولّد مسودة» → يستدعي Story Writer (`docs/03`).
- محرر صفحة-بصفحة: نص عربي + وصف المشهد + ملاحظات.
- عدّاد كلمات وتحذير إذا خرج عن مدى العمر.
- إصدارات (`StoryVersion`) مع diff وإمكانية الرجوع.
- زر «فحص السلامة والعمر» → تقرير آلي.
- زر «اعتماد النص» → ينقل الحالة إلى `CHARACTER_SETUP`.

**الشخصيات** — Character Bible:
- نموذج منظّم للبطل (شعر، بشرة، عيون، ملابس، ملمح مميز).
- خيار «توليد من الصور» (Vision) — مغلق افتراضيًا، يتطلب تفعيلًا صريحًا.
- شخصيات مساعدة + الحيوان الأليف + الخصم اللطيف.
- **Style Lock**: قفل الأسلوب البصري + لوحة الألوان + `doNotList`.
- بمجرد القفل، لا يتغير إلا بإذن `REVIEWER`.

**البرومبتات والصور** — Prompt Studio (تفصيل في `docs/03`، القسم 5):
- شبكة الصفحات، كل بطاقة فيها: نص الصفحة، البرومبت الإنجليزي، negative prompt،
  نسبة الأبعاد، المنطقة الآمنة للنص، حالة الصورة.
- أزرار: نسخ، إعادة توليد البرومبت، تحرير يدوي، رفع صورة، اعتماد، إعادة.
- **تصدير حزمة البرومبتات**: ملف `TUY-00123-prompts.md` فيه كل البرومبتات
  مرقّمة + كتلة الشخصية الثابتة + تعليمات التوليد.
- **رفع دفعي**: يسحب أمير مجلد صور → النظام يطابق بالاسم
  (`cover.png`, `p01.png` … `p16.png`, `back.png`).
- فحص آلي عند الرفع: الأبعاد، الدقة (≥ 300dpi للمقاس المطبوع)، حجم الملف.

**الكتاب** —
- اختيار قالب التنضيد، توزيع النص على الصور، ضبط المنطقة الآمنة.
- زر «ابنِ المعاينة» → PDF منخفض الدقة بعلامة مائية.
- زر «أرسل المعاينة للعميل» (يتطلب تأكيدًا بشريًا).
- زر «ملف الطباعة» → PDF بدقة كاملة + bleed 3mm + علامات قص.

**التسليم** — الطباعة، التغليف، الشحن، رقم التتبع، إغلاق الطلب،
زر «اطلب رأي العميل»، وأرشفة الأصول التسويقية إن سُمح.

### 3. المهام (Tasks)

كل طلب يولّد مهامًا تلقائيًا حسب الباقة:

```
كتابة القصة → مراجعة النص → بناء الشخصيات → توليد البرومبتات →
إنتاج الصور → مراجعة الصور → تنضيد الكتاب → QC → إرسال المعاينة →
معالجة التعديلات → ملف الطباعة → طباعة → تغليف → شحن
```

كل مهمة: `assignee` · `status` · `priority` · `dueDate` · `comments` · `files`.

## د. حالات الطلب

```php
// app/Enums/OrderStatus.php
enum OrderStatus: string
{
    case Draft             = 'draft';              // مسودة في المعالج، لم تُدفع
    case New               = 'new';                // مدفوعة، لم تُراجع
    case DataReview        = 'data_review';        // مراجعة البيانات والصور
    case OnHold            = 'on_hold';            // ناقص بيانات — تم إشعار العميل
    case Writing           = 'writing';
    case StoryReview       = 'story_review';
    case CharacterSetup    = 'character_setup';
    case PromptsReady      = 'prompts_ready';      // البرومبتات جاهزة للتوليد الخارجي
    case Illustrating      = 'illustrating';       // أمير يولّد الصور
    case ImageReview       = 'image_review';
    case BookLayout        = 'book_layout';
    case Qc                = 'qc';
    case PreviewSent       = 'preview_sent';
    case RevisionRequested = 'revision_requested';
    case Approved          = 'approved';
    case PrintReady        = 'print_ready';
    case Printing          = 'printing';
    case Packing           = 'packing';
    case Shipped           = 'shipped';
    case Delivered         = 'delivered';
    case Completed         = 'completed';
    case Cancelled         = 'cancelled';
    case Refunded          = 'refunded';
}
```

**خريطة العرض للعميل** (`OrderStatus::customerStage()`):

| حالات النظام | ما يراه العميل |
|---|---|
| `NEW`, `DATA_REVIEW`, `ON_HOLD` | حكايتك وصلتنا |
| `WRITING`, `STORY_REVIEW` | نكتب القصة |
| `CHARACTER_SETUP` → `IMAGE_REVIEW` | نرسم عالم طفلك |
| `BOOK_LAYOUT`, `QC` | نجهّز الكتاب |
| `PREVIEW_SENT`, `REVISION_REQUESTED` | بانتظار موافقتك |
| `APPROVED` → `PACKING` | في الطباعة |
| `SHIPPED` | في الطريق إليك |
| `DELIVERED`, `COMPLETED` | وصلت 🎉 |

قواعد الانتقال في `App\Services\Orders\OrderStateMachine` — لا انتقال خارج الجدول،
وكل انتقال يكتب في `order_status_history` ويطلق `OrderStatusChanged` event.
الإشعارات من الـ listener، لا من داخل الـ Action.

لا تربط السعر بالكود. التسعير يُحسب في `PricingCalculator` على الخادم دائمًا.

## ز. ما هو خارج النطاق في MVP

اكتبها في الكود كـ `// FUTURE:` ولا تبنِها:

- توليد الصور داخل النظام.
- القصة الصوتية (لكن أبقِ حقل `audioUrl` في `Product`).
- تطبيق موبايل.
- الاشتراك الشهري.
- تعدد اللغات الفعلي (البنية فقط: `lang/ar/` + `resources/js/lang/ar.json`).
- بوابة دفع مؤتمتة (يدوي/تحويل + تأكيد من الاستوديو).
- تكامل شركات الشحن (إدخال رقم التتبع يدويًا).
