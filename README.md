# طيوف | TUYOOF — حزمة التسليم لـ Claude Code

---

## ما هذه الحزمة

خطة تنفيذ كاملة لمنصة قصص الأطفال الشخصية: موقع عام + استوديو إدارة + محرك ذكاء اصطناعي.
مبنية على دراسة الجدوى والخطة التنفيذية الموجودتين في المشروع.

**المكدّس:** مشروع **Laravel 12** واحد — الباك إند Laravel، الواجهات **React 19 + TypeScript**
عبر **Inertia.js v2**، التنسيق **Tailwind CSS v4**. الموقع والاستوديو ولوحة العميل
كلها في نفس المستودع ونفس عملية البناء.

```
tuyoof-plan/
├── README.md                    ← أنت هنا
├── CLAUDE.md                    ← ضعه في جذر المستودع
└── docs/
    ├── 01-product-spec.md       المواصفات الوظيفية
    ├── 02-architecture.md       البنية + مخطط قاعدة البيانات كامل
    ├── 03-ai-engine.md          محرك القصص والبرومبتات
    ├── 04-design-system.md      الهوية والواجهات وقوالب الكتاب
    └── 05-roadmap.md            8 مراحل + أوامر جاهزة للنسخ
```

## قواعد التعامل مع Claude Code

1. **مرحلة واحدة في كل جلسة.** لا تعطه الخطة كلها دفعة واحدة — سينتج كودًا سطحيًا
   في كل مكان بدل نظام يعمل في مكان واحد.
2. **بعد كل مرحلة:** commit، ثم جلسة جديدة للمرحلة التالية.
3. **لا توافق على "خلصت" قبل تشغيل معايير القبول بنفسك.**
4. عندما ينحرف، قل: `ارجع إلى CLAUDE.md — أنت تخالف القاعدة رقم X`.
5. حدّث `CLAUDE.md` كلما اتخذتَ قرارًا جديدًا. الملف يجب أن ينمو مع المشروع.

## قرارات محسومة في هذه الخطة

| القرار | لماذا |
|---|---|
| **الاستوديو قبل الموقع** | أول 20 طلب من إنستغرام وواتساب. القدرة على التسليم قبل صفحة الهبوط. |
| **النظام يولّد برومبتات لا صورًا** | كما طلبت — أنت تولّد الصور خارجيًا وترفعها عبر Prompt Studio. |
| **`Product` وليس `Book`** | من خطتك التنفيذية — طيوف ستضم تلوينًا وبوسترات ومنتجات مدارس. |
| **مشروع واحد بلا microservices** | مطوّر واحد. تقليل السطح. |
| **VPS + Docker بدل Vercel** | Playwright لتوليد PDF يحتاج Chromium ثابت. |
| **جدول Jobs بدل Redis** | الحجم لا يبرر البنية. أضِف Redis عند تجاوز 300 طلب/شهر. |
| **`Character Bible` مقفول** | أكبر خطر تشغيلي في الدراسة هو عدم ثبات شكل الطفل. هذا هو الحل. |
| **الخصوصية كميزة بيع** | صفحة `/child-safety` مستقلة وبارزة، لا حاشية قانونية. |

## ثلاثة أشياء عليك حسمها قبل المرحلة 0

هذه لا يستطيع Claude Code اختراعها نيابةً عنك:

1. **ملفات هوية طيوف** — الألوان والخطوط الفعلية. إن لم تُسلَّم، سيُستخدم
   الاقتراح الاحتياطي في `docs/04` وستدفع تكلفة إعادة تصميم لاحقًا.
2. **بلد التشغيل والعملة** — يحدد الطباعة والتوصيل وطريقة الدفع والأسعار الحقيقية.
   الأسعار في `docs/05` تقديرية من الدراسة ولم تُختبر مع مطبعة.
3. **مقاس الكتاب النهائي** — الخطة تفترض 21×21 سم. أكّده مع المطبعة قبل
   المرحلة 3، لأن كل قوالب Blade للطباعة تُبنى عليه.
4. **PostgreSQL أم MySQL** — الخطة تفترض PostgreSQL 16. MySQL 8 يعمل بلا تغيير
   يُذكر لأن كل الحقول المركّبة `json` مع casts. احسمها قبل أول migration.

## ما هو خارج الخطة عمدًا

توليد الصور داخليًا · القصة الصوتية · تطبيق موبايل · الاشتراك الشهري ·
بوابة دفع مؤتمتة · تكامل شركات الشحن · اللغة الإنجليزية الفعلية.

دون إعادة كتابة منطق الأعمال — هذه فائدة بنية Actions.

كلها في المرحلة 7. البنية تستوعبها، لكن بناءها قبل أول 20 عميلًا مدفوعًا
هو الخطأ الأكثر شيوعًا في هذا النوع من المشاريع.
